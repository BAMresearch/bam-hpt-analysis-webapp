# Changelog

All notable changes to the T4.2 Data Analysis WebApp are documented here.

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).  
Version numbers match `flask_app/VERSION` and the `tool_version` column on summary export.

## [Unreleased]

### Added

- **Hybrid switch temperatures and test method are stored.** A hybrid profile stores the outdoor temperature where the heat pump switches on and the outdoor temperature where the boiler switches off, the Profiles page shows the water outlet calculated from heating letters A–D for each, and a results row can record the file as a separated test or a combined test; the method is not scored
- **Combined hybrid system efficiency.** A combined hybrid test shows a system efficiency beside the corrected COP on Mean Values, the corrected heating capacity divided by (gas + 1.9 × the corrected electric power); it is calculated when the page is shown and is not stored, a separated test does not show it, and the Export summary download appends the gas mean, the test method and that efficiency
- **Which hybrid tests are compared with the building load.** On Deviations, a separated hybrid test is compared with the existing heating load only at C and D, and a combined hybrid test at A–D and at the two switch temperatures stored on the profile, coloured at the same ±5 %; the other separated tests are maximum-capacity tests and their cells stay empty, as they do when no design capacity is set
- **Period Statistics and Scatter follow the same hybrid load rule.** Period Statistics colours heating capacity, and Scatter draws its heating-capacity band, only for the hybrid tests Deviations compares with the building load; a separated test at any other letter stays uncoloured with that reason in the hover, and a row with no method is unchanged
- **Hybrid switch tests are scored on Deviations.** A test stored as heat-pump on or boiler off is scored for outdoor dry bulb, wet bulb and water outlet against the setpoints the hybrid profile already calculates, with the same bands as a heating letter, when **Calculate deviations** runs; the outlet stays empty when the profile cannot calculate one, mean water temperature is not scored
- **Hybrid switch tests are scored on Guideline Windows, Period Statistics and Scatter.** A test stored as heat-pump on or boiler off is scored for outdoor dry bulb, wet bulb and water outlet with the same bands a heating letter already uses on each page; the outlet stays empty when the profile cannot calculate one, mean water temperature is not scored, a separated switch test is still not compared with the building load, and **Compute missing scores** fills Guideline Windows
- **A cooling row's capacity is compared with the building cooling load.** On Deviations, two new columns after **Mean Q dev (%)**, **Cooling load dev (kW)** and **Cooling load dev (%)**, compare a cooling row's stored cooling capacity (corrected when stored, else uncorrected) with the cooling load at its letter, the design cooling capacity × (outdoor dry-bulb − 16) / (35 − 16), and colour the percent at the same ±5 % as heating Qset; the read-only band card says so. The load is worked out when the page opens, with no new database column and no recalculation. The heating Qset cells stay empty on a cooling row, a heating row leaves the cooling cells empty, and a profile with no design cooling capacity leaves them empty too. On Scatter, a cooling-capacity axis draws that load ± 5 % for cooling points beside any heating Qset band. Guideline Windows and wet-bulb are unchanged
- **Cycle pieces on Guideline Windows for the spreadsheet.** Beside the evaluation means, each row now carries duration, Tsup, Q, P and COP for four pieces: **D1** (the `buffer_min` immediately before heating), **D2** (the defrost body), **equilibrium** and **H**, computed the same way as the evaluation columns (COP is mean Q over mean P). D1 and D2 are split from the parent start, the parent end and the stored power-transition time: a window that opens in the defrost has D2 = start → transition and D1 = transition → transition + buffer; a window that opens just after a defrost has D1 = start → start + buffer and D2 = transition → end. A later defrost in the same row is never this D2, and these are not the Period Statistics D1 / D2. A missing transition, an edge outside the parent, or an on–off or continuous row leaves a piece `n/a`, never `0`. The CSV names them `D1bufferBeforeH_*`, `D2defrostBody_*`, `eq_*` and `H_*` (`duration_s`, `Tsup_C`, `Q_kW`, `P_kW`, `COP`). The tool does not add the pieces up; combine them in the spreadsheet as duration-weighted Q over duration-weighted P. Rows stored before this show the pieces `n/a` until **Compute missing scores** runs, which fills them without moving clocks or changing eval ΔCOP
- **Water-to-water heating source is stored.** `ecodesign_heating` gains a `water_water_source` block beside the letter grid (ground heat exchanger, source inlet 10 °C for every letter, 3 K inlet − outlet for variable source flow, no outlet setpoint), returned only for `water_water` profiles. Water-to-water profiles can set `source_flow_mode`, `source_flow_type` and `source_flow_set_value` on the Profiles page, separate from the sink flow fields. Nothing is scored or coloured
- An air-to-water profile can store a cooling design capacity (`pdesignc_kw`) and a cooling flow (`cooling_flow_mode`, and for fixed mode `cooling_flow_type` and `cooling_flow_set_value`) beside the heating numbers on the Profiles page; both are typed, not calculated from each other. A cooling row's flow is compared with this stored cooling flow when the cooling flow mode is fixed and a number is stored: the same percent of set, outside-band count and instantaneous band as a heating row's flow, read from mass or volume flow by the cooling flow type, on Deviations, Guideline Windows, Period Statistics, the flow deviation plot and Scatter. With a variable or empty cooling flow mode, or fixed with no number, flow on a cooling row stays n/a; the heating flow is never used for a cooling row, and the heating flow mode does not decide it. Guideline Windows shows a cooling row's flow cells empty until **Compute missing scores** has scored them against the stored cooling flow. The cooling design capacity and wet-bulb are still not scored on a cooling row (no wet-bulb band or colour). A cooling row's water outlet is compared with its letter's `tsup_set` (A–D: 7 / 8.5 / 10 / 11.5 °C) as a whole-test mean at ±0.5 K, with no individual outlet percentage, and the deviation pop-up draws that mean band. Its outdoor dry-bulb is compared with the letter's `tdb_set` (A–D: 35 / 30 / 25 / 20 °C) with the same dry-bulb widths as heating: ±1 K on Deviations; on Guideline Windows ±1 K on each sample and ±0.3 K on the mean for interval H, equilibrium and evaluation, and ±2 K and ±0.6 K for interval S. Interval D is heating only and stays empty on a cooling row. Period Statistics colours a cooling row's dry-bulb the same way, and the pop-up draws the dry-bulb trace and band but no wet-bulb. Guideline Windows shows a cooling row's dry-bulb cells empty until **Compute missing scores** has scored them. A cooling row's inlet difference is `T_return_emu` minus `T_return_calc`, scored around 0 K with the steady-operation widths ±0.5 K on each sample and ±0.3 K on the mean, and the deviation pop-up draws that band; the −2…+2 K band stays on heating rows; a custom formula that needs a missing dry-bulb or water outlet setpoint, and Scatter, use the cooling letter for both on a cooling row, a cooling row's missing wet-bulb stays empty in a formula and a cooling point on Scatter has no wet-bulb band and no heating Qset band, and a heating letter is never used for a cooling row
- **Air-to-water cooling import map.** The import notebook's **Template** dropdown offers **Air-to-water cooling** (`hpt_aw_cooling_rev1`) for the cooling (fan-coil) workbook: its `_source` water loop becomes the usual Plotdaten water columns, `Cooling capacity (without corr)` keeps its name, and every row carries `duty` = `cooling`; heating and cooling maps refuse each other's workbook, name the Template to pick and write nothing for that sheet; the cooling template also refuses a water-to-water workbook and a hybrid workbook and names that template (**Water-to-water**, **Hybrid**). Add to DB and the main-page paste box read `duty` the same way and store the condition set `ecodesign_cooling_fan_coil` on a cooling file (a file with no `duty` stays on the heating set; a file with more than one duty is not added, and the message says so). A cooling row's wet-bulb is not scored on Deviations or on Guideline Windows (it stays n/a, never `0`, with no colour), and the heating wet-bulb rule (dry-bulb − 1 K) is not applied. Water outlet, outdoor dry-bulb, inlet difference and flow are the bullet above
- **Water-to-water and hybrid import maps.** The import notebook's **Template** dropdown now offers `hpt_ww_rev1` and `hpt_hybrid_rev1` beside air-to-water. Both read the sink side exactly like air-to-water. Water-to-water keeps the source loop under its own `_source` names and needs no outdoor air. Hybrid keeps `Heat input (at 15°C)` (gas fuel energy) as its own column; the other gas columns pass through. Gas is never added to electric power or heating capacity and never becomes a back-up heater column
- **`Q_HP`, gas heat input and the source loop are stored as means** after Add to DB: `avg_q_hp`, `avg_gas_heat_input`, and `avg_t_in_source`, `avg_t_out_source`, `avg_volume_flow_source`, `avg_mass_flow_source`, `avg_density_source`, `avg_cp_in_source`, `avg_cp_out_source`, `avg_dp_source`. A file without the column stores n/a, never `0`. They are not scored and not part of COP. On Mean Values `Avg Q HP` is a main column; the gas and source means sit with the other monitoring means

- **The eval ΔCOP on Guideline Windows can be checked.** Hovering a filled **eval ΔCOP** cell now names the two COPs it was made of — the first and the last five minutes of the saved evaluation window — with the seconds each slice covers and the 2.5 % limit, and the **CSV** carries the same two COPs and both windows beside the percentage. The formula, the window it uses and the limit are unchanged, there is no new column on the table, and an n/a cell still shows only its reason (never `0`). Rows scored before this keep their percentage without the two COPs until their clocks are saved again or **Compute missing scores** runs
- **Sliding ΔCOP figure on Guideline Windows.** A button in each row's eval ΔCOP cell opens one figure: ΔCOP of a 70-minute window walking from the saved equilibrium end to the saved H end in 5-minute steps, with a line at −2.5 %. Each point uses the first and last five minutes of its own window, with the same formula as the cell. The sheet is read once per click and never on page load. Nothing is stored, the cell stays the saved evaluation window, and the CSV is unchanged. A row with no trace (on–off, no saved equilibrium or H, or H shorter than a full 70 minutes after equilibrium) says so instead of plotting zeros
- **5-minute corrected COP on the sliding ΔCOP figure.** The same figure now also shows, on a second axis, the corrected COP of each 5-minute block from 5 minutes after the saved equilibrium end to the saved H end — the COP the ΔCOP percent is made from, with the back-up heater term the entry's own COP uses (a real backup heater is not added on top). Each ΔCOP point equals the change between two points of that line. The ΔCOP values, the −2.5 % line, the cell and its colour are unchanged; nothing is stored, and the sheet is still read once per click
- **Growing ΔCOP line on the sliding ΔCOP figure.** The same right axis now also carries ΔCOP of a growing interval: it always starts at the saved equilibrium end, so its first 5 minutes stay fixed, and its end walks to the saved H end in 5-minute steps, from two slices (10 minutes) on, with a last point exactly at H end when the step does not land there. At 70 minutes it meets the first point of the 70-minute line; after that the 70-minute window moves its first slice forward and the growing one keeps it. Below −2.5 % a point is red. The points come in the same single request and the sheet is still read once per click; the line is absent (never zeros) when H holds less than two slices after equilibrium, and a row with no 70-minute trace still shows no figure. The cell, the CSV and the 70-minute line are unchanged, and nothing is stored
- **The power-transition time is stored when a cycle is created.** Cycle Extract **Apply** (and any other insert or recalculate of a parent entry) now detects and stores `pelec_transition_time` on the new row, so that number no longer waits for Edit clocks + Save or for a dTreturn Insights cache update. On a defrost cycle the end of the defrost is the **last** time supply − return (`Ts Buh` else `T_supply`, minus `T_return_emu` — not dTreturn) crosses above `dt_hp_recover_k` and stays there for `dt_hp_recovery_hold_s` (120 s), so a one-sample flicker followed by a deeper dip cannot end a defrost and a compressor ramp-up on its own is only a hint; on–off cycles and windows that open in heating use the power event alone. Where the kind is still empty the test-condition letter helps (A/B/E/F defrost, C/D on–off; an empty or unlisted letter stays unknown, never continuous), below a stored cycle type and a defrost-indicator column. A time you typed is never overwritten, a cycle the tool cannot read stays empty (never `0`), and Apply succeeds either way. New settings in `flask_app/config/cycle_periods.json`: `dt_hp_recover_k` (0.2 K), `dt_hp_hold_s` (60 s, the cold-side test: below the threshold that long means a defrost happened) and `dt_hp_recovery_hold_s` (120 s). The default D / H / equilibrium / evaluation clocks are written from that same decision (next bullet)
- **Apply also writes the default guideline clocks.** Creating a parent entry on Cycle Extract — and any recalculate of one — now stores the D (or S) + H sub-periods, with equilibrium and evaluation inside H on defrost and continuous cycles, so a new entry is ready for Guideline Windows and the Deviations plot without opening **Edit clocks** first. Same lengths and the same rule as Edit clocks; the parent row stays the complete cycle and no second row is created. These clocks are a **default, not a confirmation**: **Edit clocks** is how you change them and **Save** is what marks them as yours. A row that already has guideline clocks, or a power-transition time you typed, is left exactly as it is — re-applying or recalculating is a skip, never a rewrite, and **Clear saved guideline clocks** then Apply, or **Edit clocks** then **Save**, is how you redo them. A window whose kind is still unknown, and one the tool cannot judge (a defrost letter with no usable supply / return series, an on–off letter with no readable power), get no clocks; the entry is stored either way, and a clock or score failure never fails Apply
- **Guideline clocks on Cycle Extract.** For the open file, **Edit clocks** opens the sub-periods on existing database entries: **D** (defrost + buffer) or **S** (standby + buffer), **H**, and — on defrost and continuous cycles — **equilibrium** then **evaluation**. Evaluation is the first `eval_min` after the first `eq_min` of H, not the last minutes of the cycle; it is omitted when H is too short. The parent row stays the full cycle. New entries also get these clocks at **Apply** (see the bullets above); **Save** is still what marks them as yours
- **Clock table and period layers** (layers off by default). Edit the power-transition time or D/S end; unlock equilibrium / evaluation to type them. **Save clocks** or **Save all clocks** stores the times on the parent entry
- **Treat unknown rows as** (defrost / on–off / continuous) fills only rows that have no kind yet. Kind **`continuous`**: no D/S; H is the parent window. Stored `other` stays unknown, not continuous
- Clock lengths in `flask_app/config/cycle_periods.json` (`buffer_min` 10, `eq_min` 60, `eval_min` 70)
- **Sink volume flow is derived from measured mass flow when it is missing.** A file with measured `mass flow` but an absent or empty `volume flow` gets `mass flow / ρ × 3600` (m³/h) at analysis time, with the same ρ as the derived mass flow (`density_sink`, else `density`, else 997 kg/m³). Measured values win, zeros included; both directions read only measured values, so a derived column never feeds the other, and a row with neither stays empty. The derived series feeds hydraulic power and the BAM pump correction, and is flashed as one warning per file. Nothing is written back to Plotdaten, and the source loop is unchanged
- **Save clocks for the open database** on Cycle Extract — the gap-fill of guideline clocks for every file that has entries in the open database (mostly entries created before Apply started filling them). Needs a database, not a loaded file. Asks first, and the confirm names how many files and entries it will write, how many already-saved entries it will leave alone, and the **Treat unknown rows as** default for rows with no kind. It then works one file at a time with a *file i of n* status, so one unreadable sheet fails that file only. Already-saved entries are never overwritten and cost no Excel read; to change a file you can see, open it and use **Save all clocks** as before. Guideline Windows stays read-only
- **Clear saved guideline clocks** on Cycle Extract — throw a clock pass away (whole database, or the loaded file) so the next fill can derive fresh clocks: running the fill again cannot, since it skips saved rows by design. Confirm names the count. It deletes the saved guideline periods and the stored power split on those rows only; the parent cycles, their means and deviations, and the older dTreturn Insights splits all stay, and the fill does not start itself. Period Statistics reads these clocks, so a cleared entry shows `n/a` there until you fill again
- **Stored interval scores on Guideline Windows.** Saving guideline clocks now also stores that entry's interval numbers (H / eq / eval percentages, D / S percentages, H / D / S means, evaluation Tsup / Q / P / COP and eval ΔCOP) next to the clocks, using the sheet the save already has open. Guideline Windows reads them back: opening the page shows the table straight away, no Plotdaten file is opened, and coming back to the page is as quick as the first visit. Rows whose clocks changed since, or whose interval bands were retuned, show `n/a` with a reason rather than an old percentage, and **Clear saved guideline clocks** removes the stored scores with the clocks; on an air-source heating row the page also scores outdoor dry-bulb minus wet-bulb against a 1 K target at ±0.6 K on the steady mean and on the standby mean and standby samples (not defrost, the parent Deviations page, water-to-water or cooling, and the separate dry-bulb and wet-bulb checks are unchanged), shown `n/a` on a row stored before this until **Compute missing scores** runs
- **Compute missing scores** on Guideline Windows — the one-off backfill for entries that have clocks but no stored scores (clocks saved before this). It asks first with the count, then works one file at a time (*file i of n*), reading each Plotdaten file once and reporting a file it cannot read. It writes the stored scores only: no proposal, no clock, no change to the parent Deviations, and it never starts on page load. Nothing else on the page does this work
- **Guideline Windows** (`/guideline_windows`) — check **saved** clocks across many entries: D / S, H, equilibrium and evaluation times, plus the entry's Tsup, Q, P and COP beside the same four on the evaluation window. Open from **Selected rows** on Mean Values, or from the navbar for the whole open database. Evaluation Q/P/COP use the same analysis-time quantities as the entry (including files that only have uncorrected Q and P). Evaluation cells stay **empty** (never `0`) when there is no evaluation window. CSV of the table; the summary export is unchanged

### Changed

- **The profile chooses the EN 14511-3:2022 pump correction.** A profile can now say whether the indoor pump is `integrated` or `not_supplied` (not part of the unit), and for an integrated pump whether it is `glandless` or `dry_motor`; a dry-motor pump needs its motor efficiency `IE` (a fraction between 0 and 1) before the correction changes, and until then Apply keeps the previous correction and shows a notice. With an arrangement set, the efficiency follows Annex F per sample (a pump not part of the unit above 300 W hydraulic power uses IE 0.88), the arrangement chooses the sign rather than the measured pressure, the power term and the capacity term are kept apart, heating subtracts the indoor capacity correction for an integrated pump and cooling adds it. A cooling row then stores its corrected cooling capacity and cooling COP in the new `avg_cooling_capacity_corr` (**Avg Cool Cap (Corr)**) and `cop_cooling_corr` (**COP cool (Corr)**), shown after **COP cool (Uncor)** and not scored. A water-to-water profile can also set a source pump, which corrects electric power only. A sample with zero hydraulic power is now corrected by zero instead of dropping out of the mean, on every path. A profile left unset keeps the previous correction. Rows already stored get the new values on the next recalculate; Guideline Windows and Period Statistics use the same correction from the profile stored on the row, so a row whose profile sets a pump shows its window Q, P and COP empty until **Compute missing scores**
- **Apply accepts a cooling Plotdaten file and stores its capacity in its own fields.** On a row whose `duty` is `cooling`, Apply stores the mean of `Cooling capacity (without corr)` in the new `avg_cooling_capacity_uncorr` (**Avg Cool Cap (Uncor)** on Means) and the cooling COP, that capacity mean divided by the mean uncorrected electric power, in the new `cop_cooling_uncorr` (**COP cool (Uncor)**). The heating capacity and heating COP fields, uncorrected, corrected and BAM-corrected, stay empty on that row, so heating and cooling never share one capacity or one COP. Electric power stays in the existing power fields. A heating row still reads only the heating capacity and leaves the two cooling fields empty, a cooling row reads only the cooling capacity, and a file with no capacity column for its duty is still refused. The cooling capacity is not scored, and a corrected cooling capacity is not stored yet. Rows already stored get the new fields on the next Apply or recalculate
- **Water-to-water heating source inlet is 10 °C.** The stored source inlet of the `water_water_source` block is now 10 °C for every heating letter (laboratory plan). The 3 K variable source-flow difference and the absence of a source outlet setpoint are unchanged. Nothing is scored or coloured
- **Eval ΔCOP on Guideline Windows is red only for a drop below −2.5 %.** The number is unchanged, (COP last − COP first) / COP first, so a drop is negative. Before, the cell turned red on the absolute value, so a rise above +2.5 % was red too; now exactly −2.5 % and any rise stay green. The header and cell hover say how the number is calculated and that −2.5 % means the COP of the last five minutes is 2.5 % below the COP of the first five. **Compute missing scores** is not needed
- **Condenser and evaporator temperatures are no longer imported or shown.** `T_in_cond`, `T_out_cond`, `T_in_evap` and `T_out_evap` are not BAM columns and not in the round-robin templates. The air-to-water map (now 0.5.2) no longer lists them, the importer leaves them out of Plotdaten when an older sheet still carries them (the import does not fail), and no `avg_t_in_cond` / `avg_t_out_cond` / `avg_t_in_evap` / `avg_t_out_evap` mean is filled for new work. They are gone from Mean Values, **Show monitoring columns** and the summary export. Databases that already have these columns keep them; nothing is dropped
- **`Avg Q HP` is on the main Mean Values table**, directly after `Avg Q HB`. `Avg Q BA` now sits with the monitoring columns, after `Avg Q HP`, and shows only with **Show monitoring columns**. Header title notes mark the model-computed columns (`Avg T Ret Calc`, `Avg T B Calc`, `Avg T H Calc` and the three Q columns), the gas heat input as hybrid-only, and the source columns as water-to-water-only. Nothing is stored or computed differently, and none of these values enters COP
- **Volume flow is converted only from a declared unit.** The importer multiplies sink `volume flow` and source `volume flow_source` by 3600 only when the template's unit row says m³/s, and says so in the import warnings. A unit row of m³/h leaves the values as they are. A small flow with no unit in the row is reported as unconverted and left unchanged; before, a median below 0.05 was silently taken as m³/s and multiplied. Stored flow stays m³/h
- **The water-to-water and hybrid maps (0.1.2) drop empty lab-corrected capacity and power, and accept the header `Total Power Input (corrected)` as `Electric Power Input (corrected)`, the same as air-to-water**
- **Outdoor air and `Q_BA` are no longer required to add a cycle.** A Plotdaten sheet without `T_outdoor (DB)`, `T_outdoor (WB)` or `Q_BA` now inserts with those means stored as n/a (never `0`); every other required column still blocks the insert when absent. The air-to-water map (0.5.0) no longer requires `Q_BA`, which the one-mass building model does not output, and keeps `Q_HP` when present. Files that carry outdoor air and `Q_BA` store the same means as before. Heating capacity, electric power and COP are unchanged for every template
- **Suggest cycles cuts termination to termination.** Frost tests run defrost termination to defrost termination (ΔT_HP, supply − return, back above 0.2 K for a 2 minute watch: new `dt_hp_recovery_hold_s` = 120 in `cycle_periods.json`), on/off tests standby termination to standby termination, and a file with no defrost and no standby is one window. Starts sit on the power drop that begins each defrost or stop; a power drop in heating with no defrost after it is not a start. The start-to-start cut is a box under **How Suggest picks Start**, the status line names the cut and test condition used, and Apply sets the matching default clocks. Entries already in the database keep theirs.
- **Guideline Windows shows the full-cycle duration in hours.**
- **Guideline Windows no longer scores mean supply temperature on the heating interval.** The ±0.5 K supply limit is the whole-test check on Deviations only. The **H mean Tsup** column is gone from the table and the CSV. The other interval scores are unchanged, and **Compute missing scores** is not needed.
- **Suggest cycles is one click.** Cycle Extract’s toolbar is now the file, **Load data** and **Suggest cycles**; **Min gap** and **Min cycle** are no longer on the page. Suggested times stay editable.
- **Review new entries no longer shows Test label.** The review modal keeps **Test cond** as the condition letter; **Test label** is stored automatically as the letter plus flow (for example `B fixed` / `A std`) and is not an extra box. Indicator and Notes stay as optional reminders — they are not required for Period Statistics. The old **dTreturn Insights** item is no longer in the navbar
- **Deviations is a full-cycle mean check, not a band editor.** The live **Configure Deviation Bands** form is replaced by a read-only card, **Permissible deviations (this page)**, still collapsed on load. It lists the three full-cycle (H+D / H+S) **mean** bands this table colours — liquid sink outlet (Tsup) ±0.5 K, liquid sink mean (Tmean, variable flow only) ±0.5 K and heating capacity Q ±5 % of Qset — reading them from the configuration already loaded, with an empty band shown as **n/a**, never `0`. There is no Save, no *Reset to Defaults*, no transient-band block and no red/yellow percentage table: bands are changed in the committed configuration files (User Guide §10), and the D / H / S interval checks live on **Guideline Windows** and **Period Statistics**. The **Design parameters** panel (Pdesign, flow mode, fixed-flow set value, *Add unit*) also leaves this page — those are unit settings and are edited on **Profiles**, which the card links to. The stored band file is untouched, and the profile pages and their APIs are unchanged. The repeating paragraph under the table is gone; the header sentence and the card are enough
- **The per-quantity Violations and % columns leave the Deviations table.** **DB**, **WB**, **dTreturn** and **flow** **Violations** and **%** are off the table, the filter row and the per-column **Update** buttons. The draft scores those sample shares **by interval**, not over the whole cycle, so on the parent row they invited a comparison the guideline does not make. They are **not** removed from the database: **Calculate Statistics** still computes and stores every one of them, and nothing drops a `dev_*` column. **Show extra columns** — still off on every load — now holds **Total Points**, the six **Max ±** excursions and **Avg Timestep (s)**, with **Actions** (Plot) still visible after it
- **Deviations colours only the three bands that exist, and never yellow.** **Mean Tsup Dev**, **Mean Tmean Dev** (variable flow only) and **Mean Q dev (%)** are green inside their band and red outside — two colours, no yellow and no half-limit step, the same reading as Period Statistics. **Mean Q dev (%)** is now read against the ±5 % Q band rather than the old red-10 / yellow-5 pair, so a 6 % cycle reads red. **Mean DB Dev**, **Mean WB Dev** and **Mean flow dev (%)** are plain numbers: the draft defines no full-cycle permissible deviation for them, and their hover says so instead of leaving a colour to imply a check. A missing mean stays `-` / **n/a** — never `0` and never red
- **Setpoints move from a column to a hover, on three pages.** The **Setpoint (DB/WB/Tsup/Q/flow)** column is off the Deviations table. In its place, the **Test Condition** badge names the letter and the climate / application slice the setpoints were read from (and says plainly when no test condition is stored), and every **mean** cell names the set that was subtracted — plus the band when that cell is coloured. **Period Statistics** and **Guideline Windows** gain the same detail on the mean cells they already had: the existing hover now carries the set as well as the signed deviation and the band. Neither page gains a Setpoint column, no score, cached value or export changed, and the sets are resolved on every page load from the entry, the unit profile and the condition set

- **Configure Deviation Bands no longer retunes the guideline-interval checks.** Interval **H** (and the equilibrium and evaluation clocks inside it) used to read its individual dry-bulb, wet-bulb and flow widths from `flask_app/permissible_deviations.json`, the file the **Configure Deviation Bands** form on Deviations writes. Saving that form therefore moved the **H / eq / eval %** columns on **Guideline Windows** and the **H band steps** on the Deviations **Plot**, which are draft guideline checks and not full-cycle parent tolerances. Those three widths are now explicit keys on Interval H in `flask_app/config/interval_deviations.json` — **the numbers are unchanged** (DB ±1 K, WB ±1 K, flow ±2.5 % of set, dTreturn ±0.5 K as before) — and equilibrium and evaluation reuse H's keys rather than a second table. D and S already had their own widths and are untouched, and the parent file keeps every number it had (dTreturn −2…2 K, mean DB 0.6 K), still drives the parent Deviations table, its colouring and the dashed parent lines on the plot. Nothing has to be recomputed: stored interval scores are carried over to the new configuration file in place when the database is opened, so **Compute missing scores** is *not* needed for this change and no cached percentage was touched. A row that was already out of date, because its clocks moved, stays out of date and still says so. An interval with no width configured is **n/a, never `0`**.
