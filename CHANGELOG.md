# Changelog

All notable changes to the T4.2 Data Analysis WebApp are documented here.

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).  
Version numbers match `flask_app/VERSION` and the `tool_version` column on summary export.

## [Unreleased]

### Added

- **The eval ΔCOP on Guideline Windows can be checked.** Hovering a filled **eval ΔCOP** cell now names the two COPs it was made of — the first and the last five minutes of the saved evaluation window — with the seconds each slice covers and the 2.5 % limit, and the **CSV** carries the same two COPs and both windows beside the percentage. The formula, the window it uses and the limit are unchanged, there is no new column on the table, and an n/a cell still shows only its reason (never `0`). Rows scored before this keep their percentage without the two COPs until their clocks are saved again or **Compute missing scores** runs
- **The power-transition time is stored when a cycle is created.** Cycle Extract **Apply** (and any other insert or recalculate of a parent entry) now detects and stores `pelec_transition_time` on the new row, so that number no longer waits for Edit clocks + Save or for a dTreturn Insights cache update. On a defrost cycle the end of the defrost is the **last** time supply − return (`Ts Buh` else `T_supply`, minus `T_return_emu` — not dTreturn) crosses above `dt_hp_recover_k` and stays there for `dt_hp_hold_s`, so a one-sample flicker followed by a deeper dip cannot end a defrost and a compressor ramp-up on its own is only a hint; on–off cycles and windows that open in heating use the power event alone. Where the kind is still empty the test-condition letter helps (A/B/E/F defrost, C/D and `C70min` on–off; an empty or unlisted letter stays unknown, never continuous), below a stored cycle type and a defrost-indicator column. A time you typed is never overwritten, a cycle the tool cannot read stays empty (never `0`), and Apply succeeds either way. New settings in `flask_app/config/cycle_periods.json`: `dt_hp_recover_k` (0.2 K) and `dt_hp_hold_s` (60 s). The default D / H / equilibrium / evaluation clocks are written from that same decision (next bullet)
- **Apply also writes the default guideline clocks.** Creating a parent entry on Cycle Extract — and any recalculate of one — now stores the D (or S) + H sub-periods, with equilibrium and evaluation inside H on defrost and continuous cycles, so a new entry is ready for Guideline Windows and the Deviations plot without opening **Edit clocks** first. Same lengths and the same rule as Edit clocks; the parent row stays the complete cycle and no second row is created. These clocks are a **default, not a confirmation**: **Edit clocks** is how you change them and **Save** is what marks them as yours. A row that already has guideline clocks, or a power-transition time you typed, is left exactly as it is — re-applying or recalculating is a skip, never a rewrite, and **Clear saved guideline clocks** then Apply, or **Edit clocks** then **Save**, is how you redo them. A window whose kind is still unknown, and one the tool cannot judge (a defrost letter with no usable supply / return series, an on–off letter with no readable power), get no clocks; the entry is stored either way, and a clock or score failure never fails Apply
- **Guideline clocks on Cycle Extract.** For the open file, **Edit clocks** opens the sub-periods on existing database entries: **D** (defrost + buffer) or **S** (standby + buffer), **H**, and — on defrost and continuous cycles — **equilibrium** then **evaluation**. Evaluation is the first `eval_min` after the first `eq_min` of H, not the last minutes of the cycle; it is omitted when H is too short. The parent row stays the full cycle. New entries also get these clocks at **Apply** (see the bullets above); **Save** is still what marks them as yours
- **Clock table and period layers** (layers off by default). Edit the power-transition time or D/S end; unlock equilibrium / evaluation to type them. **Save clocks** or **Save all clocks** stores the times on the parent entry
- **Treat unknown rows as** (defrost / on–off / continuous) fills only rows that have no kind yet. Kind **`continuous`**: no D/S; H is the parent window. Stored `other` stays unknown, not continuous
- Clock lengths in `flask_app/config/cycle_periods.json` (`buffer_min` 10, `eq_min` 60, `eval_min` 70)
- **Save clocks for the open database** on Cycle Extract — the gap-fill of guideline clocks for every file that has entries in the open database (mostly entries created before Apply started filling them). Needs a database, not a loaded file. Asks first, and the confirm names how many files and entries it will write, how many already-saved entries it will leave alone, and the **Treat unknown rows as** default for rows with no kind. It then works one file at a time with a *file i of n* status, so one unreadable sheet fails that file only. Already-saved entries are never overwritten and cost no Excel read; to change a file you can see, open it and use **Save all clocks** as before. Guideline Windows stays read-only
- **Clear saved guideline clocks** on Cycle Extract — throw a clock pass away (whole database, or the loaded file) so the next fill can derive fresh clocks: running the fill again cannot, since it skips saved rows by design. Confirm names the count. It deletes the saved guideline periods and the stored power split on those rows only; the parent cycles, their means and deviations, and the older dTreturn Insights splits all stay, and the fill does not start itself. Period Statistics reads these clocks, so a cleared entry shows `n/a` there until you fill again
- **Stored interval scores on Guideline Windows.** Saving guideline clocks now also stores that entry's interval numbers (H / eq / eval percentages, D / S percentages, H / D / S means, evaluation Tsup / Q / P / COP and eval ΔCOP) next to the clocks, using the sheet the save already has open. Guideline Windows reads them back: opening the page shows the table straight away, no Plotdaten file is opened, and coming back to the page is as quick as the first visit. Rows whose clocks changed since, or whose interval bands were retuned, show `n/a` with a reason rather than an old percentage, and **Clear saved guideline clocks** removes the stored scores with the clocks
- **Compute missing scores** on Guideline Windows — the one-off backfill for entries that have clocks but no stored scores (clocks saved before this). It asks first with the count, then works one file at a time (*file i of n*), reading each Plotdaten file once and reporting a file it cannot read. It writes the stored scores only: no proposal, no clock, no change to the parent Deviations, and it never starts on page load. Nothing else on the page does this work
- **Guideline Windows** (`/guideline_windows`) — check **saved** clocks across many entries: D / S, H, equilibrium and evaluation times, plus the entry's Tsup, Q, P and COP beside the same four on the evaluation window. Open from **Selected rows** on Mean Values, or from the navbar for the whole open database. Evaluation Q/P/COP use the same analysis-time quantities as the entry (including files that only have uncorrected Q and P). Evaluation cells stay **empty** (never `0`) when there is no evaluation window. CSV of the table; the summary export is unchanged

### Changed

- **Review new entries no longer shows Test label.** The review modal keeps **Test cond** as the condition letter; **Test label** is stored automatically as the letter plus flow (for example `B fixed` / `A std`) and is not an extra box. Indicator and Notes stay as optional reminders — they are not required for Period Statistics. The old **dTreturn Insights** item is no longer in the navbar
- **Deviations is a full-cycle mean check, not a band editor.** The live **Configure Deviation Bands** form is replaced by a read-only card, **Permissible deviations (this page)**, still collapsed on load. It lists the three full-cycle (H+D / H+S) **mean** bands this table colours — liquid sink outlet (Tsup) ±0.5 K, liquid sink mean (Tmean, variable flow only) ±0.5 K and heating capacity Q ±5 % of Qset — reading them from the configuration already loaded, with an empty band shown as **n/a**, never `0`. There is no Save, no *Reset to Defaults*, no transient-band block and no red/yellow percentage table: bands are changed in the committed configuration files (User Guide §10), and the D / H / S interval checks live on **Guideline Windows** and **Period Statistics**. The **Design parameters** panel (Pdesign, flow mode, fixed-flow set value, *Add unit*) also leaves this page — those are unit settings and are edited on **Profiles**, which the card links to. The stored band file is untouched, and the profile pages and their APIs are unchanged. The repeating paragraph under the table is gone; the header sentence and the card are enough
- **The per-quantity Violations and % columns leave the Deviations table.** **DB**, **WB**, **dTreturn** and **flow** **Violations** and **%** are off the table, the filter row and the per-column **Update** buttons. The draft scores those sample shares **by interval**, not over the whole cycle, so on the parent row they invited a comparison the guideline does not make. They are **not** removed from the database: **Calculate Statistics** still computes and stores every one of them, and nothing drops a `dev_*` column. **Show extra columns** — still off on every load — now holds **Total Points**, the six **Max ±** excursions and **Avg Timestep (s)**, with **Actions** (Plot) still visible after it
- **Deviations colours only the three bands that exist, and never yellow.** **Mean Tsup Dev**, **Mean Tmean Dev** (variable flow only) and **Mean Q dev (%)** are green inside their band and red outside — two colours, no yellow and no half-limit step, the same reading as Period Statistics. **Mean Q dev (%)** is now read against the ±5 % Q band rather than the old red-10 / yellow-5 pair, so a 6 % cycle reads red. **Mean DB Dev**, **Mean WB Dev** and **Mean flow dev (%)** are plain numbers: the draft defines no full-cycle permissible deviation for them, and their hover says so instead of leaving a colour to imply a check. A missing mean stays `-` / **n/a** — never `0` and never red
- **Setpoints move from a column to a hover, on three pages.** The **Setpoint (DB/WB/Tsup/Q/flow)** column is off the Deviations table. In its place, the **Test Condition** badge names the letter and the climate / application slice the setpoints were read from (and says plainly when no test condition is stored), and every **mean** cell names the set that was subtracted — plus the band when that cell is coloured. **Period Statistics** and **Guideline Windows** gain the same detail on the mean cells they already had: the existing hover now carries the set as well as the signed deviation and the band. Neither page gains a Setpoint column, no score, cached value or export changed, and the sets are resolved on every page load from the entry, the unit profile and the condition set

- **Configure Deviation Bands no longer retunes the guideline-interval checks.** Interval **H** (and the equilibrium and evaluation clocks inside it) used to read its individual dry-bulb, wet-bulb and flow widths from `flask_app/permissible_deviations.json`, the file the **Configure Deviation Bands** form on Deviations writes. Saving that form therefore moved the **H / eq / eval %** columns on **Guideline Windows** and the **H band steps** on the Deviations **Plot**, which are draft guideline checks and not full-cycle parent tolerances. Those three widths are now explicit keys on Interval H in `flask_app/config/interval_deviations.json` — **the numbers are unchanged** (DB ±1 K, WB ±1 K, flow ±2.5 % of set, dTreturn ±0.5 K as before) — and equilibrium and evaluation reuse H's keys rather than a second table. D and S already had their own widths and are untouched, and the parent file keeps every number it had (dTreturn −2…2 K, mean DB 0.6 K), still drives the parent Deviations table, its colouring and the dashed parent lines on the plot. Nothing has to be recomputed: stored interval scores are carried over to the new configuration file in place when the database is opened, so **Compute missing scores** is *not* needed for this change and no cached percentage was touched. A row that was already out of date, because its clocks moved, stays out of date and still says so. An interval with no width configured is **n/a, never `0`**. One leftover detail: the per-interval block that **Calculate** on Deviations writes behind the scenes now reports H, equilibrium and evaluation as *bands not configured*, the same as D and S; that block has no table on any page, and the Guideline Windows columns are where these intervals are scored
- **Period Statistics reads the means in colour, and Guideline Windows can put its mean deviations away.** A mean on Period Statistics that has a draft **mean** band is now shown green inside the band and red outside, with the signed deviation and the band on hover; the cell keeps the number it always had — there is no second column and no third colour. Coloured: **T_db** and **T_wb** on every interval group (H / On ±0.3 / ±0.4 K, D ±1.5 / ±1.0 K, S / Off ±0.6 K), **dT avg** and flow on **H** / **On** (±0.3 K, ±1 % of set), flow on **S** / **Off** (±2.5 % of set), and on the full cycle **D+H** / **Off+On** only: **Ts Buh** ±0.5 K, **T_mean** ±0.5 K (variable-flow tests) and **Q** ±5 % of Qset. Everything else keeps the plain number — including **Ts Buh** on H / On, because the outlet mean is a full-cycle check and not an interval one — and so do duration, P, COP, **dT min** and **dT max**. A cell stays uncoloured, never red and never `0`, when the mean is missing, when the test condition has no setpoint, and on the flow columns of a variable-flow test; hover says which. The split-span pieces revealed by **Show split spans** read the **D** / **S** bands. Nothing else moved: the numbers, the identity freeze, the tabs, the dropdowns and **Export CSV** (numbers only, no colour) are as before, no Plotdaten file is opened, and neither band file was retuned. On **Guideline Windows**, the three **mean deviation** groups (H, D and S, **H mean Tsup** among them) now sit behind one **Show mean deviations** checkbox, off on every load and display only: the individual **%**, the clock times, the entry and evaluation means and **eval ΔCOP** are never hidden, and **Download CSV** keeps every column
- **Period Statistics is down to the columns the page is for.** The second **T_mean avgs** column (the mean of the averages) is gone from the table and from **Export CSV** — one **T_mean**, the logged mean, is what the page shows. It is still computed and still stored with the sub-periods for the pages that read it. The split spans **D1** / **D2** and **Off1** / **Off2** (and **On1** / **On2** where a row has them) now sit behind one **Show split spans** checkbox, **off every time the page loads**: the unions **D** / **Off**, **H** / **On** and the full cycle **D+H** / **Off+On** are always shown. The checkbox changes the display only — the pieces are still pivoted, the CSV still writes every column, and nothing is saved between visits (this is not the **Show monitoring columns** toggle on Data, which does write a file). Everything else on the page is untouched: the identity block through **clocks** stays frozen, the **All / Defrost / On–Off** tabs, the three dropdowns, the 10 min buffer, **dT min / avg / max** and the extra T / flow columns (`T_db`, `T_wb`, `Ts Buh`, `m_flow`, `v_flow`) are as before, and *empty is n/a, never `0`*
- **Deviations drops the four individual Tsup columns and hides the violation tail.** **Tsup Violations**, **Tsup %**, **Max Tsup +** and **Max Tsup −** are **removed** from the table and from the per-column filters: the draft gives the liquid-sink outlet a **mean** band only, so an individual percentage against it was never a check the analyst could use. **Mean Tsup Dev (K)** stays on the table, the Tsup **plot** stays the mean ±0.5 K check, and **Q** is unchanged. With those columns gone, the transient **Supply Temp (Tsup)** band and the **Tsup** row of the violation-colouring table lost their purpose too; `permissible_deviations.json` keeps its numbers either way. The stored `dev_tsup_*` columns are **not** deleted and **Calculate** still writes them. **Show extra columns** — off on every load — keeps **Total Points**, the remaining **Max ±** columns and **Avg Timestep (s)**, with **Actions** (Plot) still visible after it. What stays on screen: **#** through **Duration (s)** (still frozen), COPCorrwBUH, Cop Carnot Corr, Test Condition, the **Mean** DB / WB / Tsup / Tmean deviations, **Mean Q** (kW and %) and **Mean flow %**. The per-column **Update** buttons sit on those extra columns, so tick the box to reach one; **Calculate Statistics** is where it was
- **Deviations says what the page is, in one sentence.** Next to *Analyze temperature deviations from setpoints…* the page now states that these are **full-cycle parent** checks and that the interval (D / H / S) scores are on **Guideline Windows**. The **Database Relationship** box and the **T_outdoor (WB)** wetbulb / relative-humidity paragraph are gone; **Filtering Help** stays collapsed where it was. **Calculate Statistics** is unchanged
- **The three wide tables scroll inside a box, and their headers and identity columns stay put.** **Period Statistics**, **Guideline Windows** and **Deviations** now use the pattern Mean Values already had: the table scrolls sideways and down inside its own box with visible scrollbars, instead of the page growing wider than the window. The header rows stay while you scroll down — on Period Statistics the **group** row and the **metric** row stack instead of landing on top of each other, and on Deviations the column titles stay above the filter row — and the identity columns stay while you scroll sideways: **rowid … clocks** on Period Statistics, **# … Kind** on Guideline Windows, **File Name … Duration (s)** on Deviations. Chrome only: no column moved, none was added or hidden, and the numbers, the badges, **Calculate** and the CSV columns are unchanged
- **Period Statistics loads in one pass.** The page read `cycle_periods` once per listed entry, so a few hundred cycles meant a few hundred queries; it now reads both period sources in one query each and keys them per parent in memory. It also stopped writing a full JSON copy of every row into the HTML, which each per-column filter box then re-parsed on every keystroke. Same rows, same D / H / Off / On pivot, same *empty is n/a, never 0*, same one engine per parent
- **Period Statistics filters are a few dropdowns.** The filter box under every column is replaced by **unit**, **test condition** and **COP dataset** above the table, the way Guideline Windows already works. They hide rows in the browser: nothing reloads and no Plotdaten file is opened. The **All / Defrost / On–Off** tabs are unchanged, and **Export CSV** still writes the rows you can see
- **Shorter page text on Period Statistics and Guideline Windows.** Period Statistics keeps one sentence saying the splits are the clocks saved on **Cycle Extract**, 10 min after D **and** after S, and that an entry without them stays empty; the toolbar line that repeated the buffer and the line about **Notes** `drop` / `ramp` are gone. Guideline Windows is down to one short paragraph — read-only check of **saved** clocks, the % and mean deviations against the draft bands, eval ΔCOP, and unsaved proposals do not appear. The two long paragraphs about where the numbers come from and what **#** is now live on the **Compute missing scores** hover and in the **User Guide**. Wording only: no number, band or column changed
- **Suggest cycles leaves out a window that never defrosted.** Detection is unchanged — the suggestions are still cut **drop to drop** and **Min gap** still merges them the same way — but on a file whose test condition is a defrost letter (A/B/E/F and the BUH variants) a suggested window is now dropped when supply − return (`Ts Buh` else `T_supply`, minus `T_return_emu`) never stays **below** `dt_hp_recover_k` for `dt_hp_hold_s`, so a compressor wiggle that is not a defrost no longer becomes a candidate cycle. The same rule and the same thresholds the clock kind already uses; a single sample under the threshold is still a flicker. Nothing is filtered on a C/D, empty or unlisted letter (standby is a power stop, and an unknown letter is never read as defrost), nor on a window whose supply / return series cannot be read, and if the filter would leave no suggestion at all the full drop-to-drop list is kept instead. Apply, **Edit clocks**, **Save**, Period Statistics and Guideline Windows are unchanged
- **Period Statistics reports both standby spans of a cycle that is cut through S.** A parent that opens in standby, heats and drops back to standby before its end stores two `off` sub-periods, and the table used to show only the first: **Off** duration, Q, P, COP and dTreturn were under-reported. **Off** is now the union of the spans — durations added, means weighted by duration, dT min the lowest and dT max the highest — with **Off1** and **Off2** columns for the pieces, exactly as **D** / **D1** / **D2** already work on a defrost cycle. The on–off column order is Off, Off1, On, Off2, Off+On, and the Off1 / Off2 columns appear only on entries that have two spans, so a one-standby entry looks as it did. Reading only: the clocks themselves, Cycle Extract Apply and Save, Guideline Windows and dTreturn Insights are unchanged
- **Period Statistics now reads the clocks saved on Cycle Extract.** The D / H and Off / On splits on that page are the guideline sub-periods stored by **Apply** or **Save all clocks** — 10 min after the defrost **and** 10 min after the restart, the same buffer on both — instead of the older dTreturn Insights cache. **Notes** no longer need `drop` / `ramp` and the cycle type may still be `other`: an entry is listed because it has clocks, and the **All / Defrost / On–Off** tabs follow the saved period types. A continuous cycle shows its H with D and Off left empty; an entry with no clocks stays `n/a` (never `0`) and the full-cycle **D+H** / **Off+On** columns still come from the parent row. Entries that only carry the old `auto_pelec` cache keep showing it under the old rule, and the two are never mixed on one entry. The **Buffer (s)** dropdown is gone — the length lives in `flask_app/config/cycle_periods.json` (`buffer_min`), and changing it means saving the clocks again. dTreturn Insights, Cycle Extract, Guideline Windows and the parent Deviations are unchanged
- **The test-condition letter is now checked against the window you extracted.** A cycle whose kind is only a hint — from the letter, from a stored cycle type, or from **Treat unknown rows as** — is read as **continuous** when that window carries no trace of the condition: a defrost hint whose supply − return (`Ts Buh` else `T_supply`, minus `T_return_emu`) never stays **below** `dt_hp_recover_k` for `dt_hp_hold_s` (a single sample under the threshold is a flicker, and a compressor dip is not a defrost), or an on–off hint with no compressor power stop in the window. Continuous means H is the whole parent window with equilibrium and evaluation from its start, and no D or S. **Apply** and **Edit clocks** use the same rule, so a row is read the same way in both; on Apply the transition time then stays empty (never `0`) and the row is **not** marked as a failed detection. A kind you set yourself, a defrost-indicator column, clocks already saved with a D or S span, and a transition time already stored or typed are never changed this way, and a window with no usable supply / return series keeps its kind rather than becoming continuous. An empty or unlisted letter is still never promoted to defrost. Thresholds, the parent rows, Period Statistics, Suggest cycles and the Guideline Windows scores are unchanged
- **Cycle Extract clock buttons renamed.** **Propose guideline clocks** is now **Edit clocks**, and **Save all proposed** is now **Save all clocks**; the per-row **Save clocks** keeps its name. Wording only: the button opens the D / H / equilibrium / evaluation clocks of the loaded file so you can change them and writes nothing, a stored power-transition time is reused rather than overwritten, saved clocks still draw on **show** with no click, and **Save clocks** / **Save all clocks** is still what stores. Detection, Apply, the saved data and the API are unchanged
- Proposing clocks no longer requires Notes `drop` / `ramp`
- Partner **User Guide** describes how to operate guideline clocks and Guideline Windows; interval bands, ΔCOP and the dTreturn definition live in the **Analysis Guide**. The **Analyst Quick Guide** includes the optional clock step
- **Guideline Windows** now opens on **`#`** — the entry's position in the open database, the same number it carries on Data and on Deviations — instead of the internal database id, which has gaps after a deletion. A **COP dataset** column (`YES` / `NO` / blank) sits beside the other entry columns. Three filters above the table (kind; COP dataset; with or without saved clocks) narrow it in the browser: they hide rows without renumbering `#`, open no Plotdaten file and recompute nothing, **Clear filters** resets them, and the status line ends with *Showing X of Y rows*. **Download CSV** writes the filtered table, with `#` and COP dataset and without the database id. The wide table now scrolls sideways inside its own box, with the scrollbar under the table, instead of sliding the whole page. **Load all entries in the open database** is gone — the page loads that table itself; **Load the selected row(s)**, **Compute missing scores** and **Download CSV** are unchanged
- Opening **Guideline Windows** now shows the table for the open database instead of an empty page — since the scores are stored, that is a database read and costs nothing. The buttons still control what is loaded
- Scoring an interval no longer prints a `cap value` or `Electrical power input BUH` line per cycle to the console
- **Guideline Windows** now shows H / eq / eval **DB %**, **WB %**, **flow %** and **dTreturn %** (Interval H bands on each saved window) and evaluation **ΔCOP** (first 5 min against last 5 min of the saved evaluation window, limit 2.5 %) when you load the rows. There is no interval Tsup %. The extra **Deviations by guideline interval** table is removed; parent Deviations stays one table (full-cycle Tsup % and dTreturn −2…+2 K unchanged)
- Guideline Windows DB / WB / flow % use the same parent-window series as Deviations Calculate (stored time series or Plotdaten plus derived mass flow), not only the raw Excel cache. A failed window score puts the scorer's reason on the n/a cell (hover). Stored `dev_db_setpoint` is used if the live outdoor-setpoint lookup is empty
- **Guideline Windows** scores **D** and **S individual %** on the union of saved spans (D: outdoor DB ±5 K and dTreturn ±2 K; S: DB/WB ±2 K, flow ±2.5 % on fixed-flow tests, dTreturn ±1 K). Two stored D (or S) spans are one number, not two. A defrost row leaves S n/a; an on–off row leaves D n/a. Parent Deviations is unchanged
- **Guideline Windows** also shows **H / D / S mean deviations** — one signed arithmetic mean per interval against its setpoint, in K (or % of set for flow), not a share of samples. H (the saved heating or `on` window): DB ±0.3 K, WB ±0.4 K, Tsup ±0.5 K, dTreturn ±0.3 K, flow ±1 % on fixed-flow tests. D (union of saved spans): DB ±1.5 K, WB ±1.0 K. S (union of saved spans): DB ±0.6 K, WB ±0.6 K, flow ±2.5 %. Cells the draft leaves blank stay n/a, never `0`; hover gives the band or the reason. Full-cycle mean Tsup, Tmean and Q stay on Deviations, and the parent bands are unchanged
- **Cycle Extract** Period layers (still off by default) draw D/S, H, equilibrium and evaluation on the existing chart. There is no Tsup band on that page. The Deviations Plot shades saved guideline D/S, H, equilibrium and evaluation on DB/WB, Tsup, dTreturn and flow. Guideline Windows stays a table; Tsup % is unchanged
- **Deviations Plot** is now **one figure per quantity** in one modal: outdoor DB/WB (air-source only), Tsup, dTreturn, and flow on fixed-flow tests. The separate **Flow** button is gone — flow comes back with the rest. Each trace is drawn once; the band is what changes. With **saved** guideline clocks the filled band is stepped at the clock edges with the per-interval individual half-widths (DB ±5 / ±1 / ±2 K on D / H / S, dTreturn ±2 / ±0.5 / ±1 K, flow ±2.5 % on H and S) and the parent / full-cycle limits stay visible as dashed lines; without clocks it is the full-cycle band on its own and the modal says so. Equilibrium and evaluation reuse the H width; a quantity the draft leaves n/a has no fill on that stretch. Tsup never steps — the draft gives the liquid sink outlet only a mean band, so that figure stays the mean ±0.5 K check. A variable-flow test simply has no flow figure. The Deviations table still scores the full cycle and Guideline Windows stays the per-interval table; parent bands are unchanged
- **Cycle Extract** can now *look* at saved clocks without re-deriving them. Loading a file brings the stored guideline periods with it, so **show** is available for any row that already has saved clocks (as well as for any row you have open in Edit clocks) and the Period layers draw the **open** clocks while you edit a row and the **saved** bands otherwise. Layers stay off by default and still draw only ticked rows. **Edit clocks** writes nothing; **Save clocks** and **Save all clocks** are what store. Open clocks that no longer match the stored rows are marked ≠ saved and nothing is written until you save
- A **second D / S start** you typed survives Save and reload: the next **Edit clocks** reads it back from the stored clocks instead of re-detecting the drop, and a cycle you forced to one span stays one span. **reset** on that row still drops it and detects again

### Fixed

- A cycle cut from one defrost (or standby) **end** to the next now gets a **second D / S** span; a cut from start to start stays one span
- Changing **Treat unknown rows as** updates Kind and the clocks immediately. If a clock button reports that the server did not answer with JSON, restart the app and reload the page
- A missing outdoor dry-bulb setpoint no longer blanks Tsup, dTreturn or flow % on Deviations Calculate or Guideline Windows H / eq / eval
- Variable-flow n/a hover on flow % names the variable-flow skip instead of a generic “does not apply”
- Deviations Plot now finds the entry by `rowid` (and compares `data_set` as a number), so saved guideline clocks actually shade the figures
- Flow Plot uses the entry’s unit profile and any stored flow set; a missing mass-flow column is not treated as “no flow set”

First tagged release for HPT T4.2 air-to-water analysis.

### Changed

- **Derived mass flow — one rule for BAM and HPT** (`derive_mass_flow_if_needed()` in `flask_app/app.py`): measured `mass flow` always wins and is never overwritten (zeros are measurements); an empty column counts as missing; rows without a measured value are derived as `volume flow [m³/h] / 3600 × ρ`, with ρ per row from `density_sink`, else `density`, else 997 kg/m³. A density outside 900–1100 kg/m³ is rejected for that row in favour of 997 with a warning. Analysis-time only — nothing is written back to Plotdaten
- **Import map `hpt_aw_rev1` 0.4.0:** `Backup heater Input (optional)` maps to `Real BUH power input` (monitoring mean only; never sets `has_buh`). `Virtual Back-up` → `Electrical power input BUH` remains the series used for BUH corrections. `cp_out_sink` / `cp_in_sink` keep the `_sink` suffix; `rho_sink` maps to `density_sink`; sheet `F` is expected
- Single Plotdaten column layout for BAM and HPT air-to-water paths
- Condition set display uses Ecodesign heating naming (`BAM_RRT` remains an internal alias)
- Mean Tmean deviation uses profile `flow_mode` (fixed vs variable), not filename heuristics
- Example UI text uses HPT naming
- **Means / review UI:** compact selected-rows toolbar, sticky identity columns, auto-filled HP ID and Test label on new-entry review, cycle-pipeline fields hidden on Means unless turned on, Notes `drop` / `ramp` required to split defrost and on/off sub-periods

### Compatibility

- Existing BAM databases gain new mean columns by `ALTER TABLE … ADD COLUMN` only. The `results` table is never dropped; existing rows stay valid
- BAM Plotdaten files are unaffected: `Electrical power input BUH` keeps its name and meaning

### Security / sharing

- Repository contains **code, templates and documentation only** — no measurement Excel or SQLite databases
- `.gitignore` excludes data paths (`Rohdaten/`, `Plotdaten/`, `*.xlsx`, `*.db`, local `config.json`)
